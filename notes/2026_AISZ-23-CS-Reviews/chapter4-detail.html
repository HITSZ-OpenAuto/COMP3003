01

IPv4 首部逐 bit 读取

考法：给十六进制首部，要求读 IHL、Total Length、Flags/Offset、TTL、Protocol、源/目的 IP。

定义

IPv4 首部最小 20B，由多个固定字段组成；首部长度字段 IHL 决定首部实际长度，Total Length 决定整个 IP 数据报长度。

解释

  • Version 4bit：IPv4 值为 4；IHL 4bit，单位是 4B，IHL=5 表示 20B。
  • Total Length 16bit：IP 首部 + IP 数据的总字节数，不包含以太网头尾。
  • TTL 8bit 每过一个路由器减 1；Protocol 8bit 指示上层协议，TCP=6、UDP=17、ICMP=1。
  • Source IP 和 Destination IP 各 32bit，按 4 个字节转十进制点分格式。

做题步骤

  • 先把首字节拆成高 4bit Version 和低 4bit IHL。
  • 再读 Total Length：两个字节十六进制转十进制。
  • 数据长度 = Total Length - IHL*4。
  • 最后读 TTL、Protocol、Checksum、源/目的 IP；不要把链路层填充算进 IP 总长度。

为什么这样设计

  • IHL 允许 IPv4 带可变长度选项；Total Length 让接收方知道 IP 数据报到哪里结束。
  • TTL 防止路由环路中的数据报永远存在；Protocol 让 IP 能把数据交给正确上层协议。

作业/考试例子

作业二中 Total_len=0x0054=84B，IHL=5，所以首部 20B，IP 数据部分长度为 84-20=64B。

02

Flags + Fragment Offset：不要把 3 bit Flags 都叫 MF

考法：给 16bit 分片字段，要求读 DF/MF、片偏移；或给 MTU 算每片长度、MF、offset。

定义

IPv4 分片控制字段由 Identification 16bit、Flags 3bit 和 Fragment Offset 13bit 组成；片偏移单位是 8B。

解释

  • Flags 三位依次是 Reserved、DF、MF；MF 只是第三位，不是整个 3bit 字段。
  • DF=1 表示禁止分片；MF=1 表示后面还有分片；最后一片 MF=0。
  • Fragment Offset 13bit 表示本片数据在原始 IP 数据部分中的偏移，单位为 8B。

做题步骤

  • 读 16bit 分片字段时，先取最高 3bit 为 Flags，再取低 13bit 为 offset。
  • 分片计算先算原数据长度：原 IP 总长度 - 原 IP 首部长度。
  • 每片最大数据 = floor((MTU - IP首部) / 8) * 8；除最后一片外都用 8B 整倍数。
  • 每片总长度 = 该片 IP 首部 + 该片数据；offset = 该片数据起点 / 8。

为什么这样设计

  • offset 用 8B 为单位可以用 13bit 表示更大的偏移范围。
  • 重组只在目的主机做，中间路由器无需保存所有分片状态，减少路由器复杂度。

作业/考试例子

0x5850 = 010 1100001010000，其中 Flags=010，所以 DF=1、MF=0；Offset=0x1850，实际字节偏移为 0x1850*8。

03

最长前缀、子网与 CIDR：按 bit 比，不按十进制感觉猜

考法：给路由表和目的地址选下一跳；给地址块划分等长子网；写默认路由。

定义

CIDR 用 a.b.c.d/x 表示前 x bit 是网络前缀；最长前缀匹配是在所有匹配路由中选择前缀长度最大的表项。

解释

  • IP 地址属于接口，不属于整台路由器；路由器有多个接口时通常有多个 IP。
  • 默认路由是 0.0.0.0/0，匹配所有地址但优先级最低。
  • 等长子网划分借 k 位可得到 2^k 个子网，块大小由剩余主机位决定。

做题步骤

  • 最长前缀题：把关键字节转二进制，只比较前缀覆盖的 bit。
  • 子网题：先确定要几个子网，借几位；再写新前缀、块大小、网络号、广播地址。
  • 新增主机路由用 /32；新增默认路由用 /0。

为什么这样设计

  • 最长前缀让路由聚合和更具体例外路由可以同时存在。
  • CIDR 摆脱传统 A/B/C 类地址限制，提高地址分配和路由聚合效率。

作业/考试例子

作业二中 /28 与 /30 同时匹配时，/30 更具体；新增某个单独主机应写 131.128.55.33/32，而默认项应是 0.0.0.0/0。

04

ARP：同网段解析下一跳 MAC

考法：问 ARP 请求/应答谁广播谁单播；跨网段时 IP 和 MAC 哪些变。

定义

ARP 在同一链路内把下一跳 IP 地址解析为 MAC 地址；它不负责解析远端网络主机的 MAC。

解释

  • ARP Request 通常广播，ARP Reply 通常单播。
  • 同一局域网内发给目标主机；跨网段时发给默认网关的 MAC。
  • 端到端 IP 源/目的通常不变，但每一跳以太网源/目的 MAC 都会重写。

做题步骤

  • 先判断目的 IP 是否同子网。
  • 同子网：ARP 目的主机 IP；不同子网：ARP 默认网关接口 IP。
  • 写每一跳帧时，IP 地址看端到端，MAC 地址看本链路下一跳。

为什么这样设计

  • IP 负责跨网络寻址，MAC 只在当前链路有效。
  • ARP 缓存带 TTL，避免每个分组都广播查询。

作业/考试例子

主机 H1 访问外网服务器时，IP 目的地址是服务器 IP，但第一跳以太网目的 MAC 是默认网关 MAC。

05

DHCP：DORA 状态过程

考法：DHCP 基于 UDP，四步 Discover/Offer/Request/ACK，返回 IP/掩码/网关/DNS。

定义

DHCP 让新接入主机自动获取 IP 地址、子网掩码、默认网关、DNS 服务器和租期等参数。

解释

  • 客户端初始没有 IP，所以 Discover 常用广播。
  • DHCP 运行在 UDP 上，服务器端口 67，客户端端口 68。
  • 四步 DORA 中，Request 既可确认选择某个 Offer，也可在续租时请求继续使用地址。

做题步骤

  • 记顺序：Discover 找服务器，Offer 给方案，Request 选方案，ACK 确认租约。
  • 若题目问“能不能跨网段”，补充 DHCP relay 可转发请求。
  • 若问返回内容，不只写 IP，还要写掩码、网关、DNS、租期。

为什么这样设计

  • 广播解决客户端初始无地址的问题。
  • 租期机制允许地址回收和移动主机重新配置。

作业/考试例子

期末填空问 DHCP 基于什么传输层协议：UDP；问四个报文：Discover、Offer、Request、ACK。

06

NAT：出站改源，回包改目的

考法：给内网主机、公网 NAT 地址和服务器，要求写转发前后源/目的 IP/端口。

定义

NAT 通过地址和端口转换，让多个私有地址主机共享公网地址访问外网，并用转换表匹配返回报文。

解释

  • 出站：源 IP/源端口从内网地址改成 NAT 公网地址/新端口，目的 IP/端口通常不变。
  • 入站回包：目的 IP/目的端口从 NAT 公网地址/端口改回内网主机地址/端口。
  • NAT 表通常记录 WAN 侧二元组与 LAN 侧二元组的映射。

做题步骤

  • 先画出方向：内网 -> 外网 是出站，外网 -> 内网 是回包。
  • 出站只改源；回包只改目的；除非题目有特殊代理设定。
  • 把端口也写上，否则多个内网主机同时访问同一服务器无法区分。

为什么这样设计

  • 私有 IPv4 地址不能在公网路由，NAT 用公网地址代表内网主机。
  • 端口复用让一个公网 IP 可以同时承载大量内部连接。

作业/考试例子

作业二 NAT 题中 H1 出站前源 IP 是 172.18.1.33，经过 R2 后源 IP 变成 203.10.2.3，目的 IP 仍是 213.48.226.31。

07

RIP、OSPF、BGP：算法、范围和更新状态

考法：判断协议类型、度量、AS 内/AS 间、RIP 距离 16、OSPF 泛洪、BGP 路径向量。

定义

RIP 是 AS 内距离向量协议，OSPF 是 AS 内链路状态协议，BGP 是 AS 间路径向量协议。

解释

  • RIP 与邻居交换距离向量，度量是跳数，16 表示不可达。
  • OSPF 泛洪链路状态通告，每个路由器拿到拓扑图后用 Dijkstra 算最短路径。
  • BGP 基于 TCP 会话通告可达前缀和 AS-PATH 等属性，策略比纯最短路径更重要。

做题步骤

  • RIP 表更新：收到邻居通告后先给距离 +1，再与现有表项比较。
  • OSPF 题写清 LS Advertisement 泛洪，不是只发给一个邻居。
  • BGP 题写 AS 间、TCP、路径向量、策略。

为什么这样设计

  • RIP 简单但收敛慢，适合小网络。
  • OSPF 掌握全局拓扑，收敛快但状态更多。
  • BGP 要表达商业关系和策略，不能只按跳数选路。

作业/考试例子

作业二 RIP 表中收到邻居路由后，每条候选距离先加 1；若距离更短或下一跳相同需要更新。

08

IPv6、隧道与分片：作业二最后一题

考法：IPv6 地址展开、IPv6-in-IPv4 隧道外层首部、经 IPv4 链路分片计算。

定义

IPv6 使用 128bit 地址和固定 40B 基本首部；隧道把 IPv6 分组作为 IPv4 数据报的数据部分穿越 IPv4 网络。

解释

  • IPv6 地址中 :: 只能使用一次，用来压缩连续的 0 组。
  • IPv6 基本首部固定 40B，没有 IPv4 首部校验和。
  • IPv6-in-IPv4 隧道中，外层首部是 IPv4 首部；若外层 IPv4 数据报超过链路 MTU，按 IPv4 分片规则切。

做题步骤

  • 展开地址：每组补足 4 个十六进制数字，:: 补够缺失的 0000 组。
  • 隧道总长度：外层 IPv4 首部 + 内层 IPv6 分组长度。
  • 分片时把外层 IPv4 数据部分视为要切的数据，offset 仍以 8B 为单位。

为什么这样设计

  • 隧道让 IPv6 可以逐步部署，不需要所有中间网络同时升级。
  • IPv6 路由器不分片，目的是让路由器处理更快，把路径 MTU 处理交给端系统。

作业/考试例子

作业二中内层 IPv6 总长度为 5000+40=5040B，外层 IPv4 总长度为 5040+20=5060B；若 MTU=720，则每片外层数据最大 floor((720-20)/8)*8=696B。

知识点总结

  • 客户/服务器结构中服务器常在线、地址稳定，客户端主动请求服务。
  • P2P 中节点直接通信，具有自扩展性，但管理更复杂，节点可能频繁上下线和改变 IP。
  • 混合结构可让搜索/索引用 C/S，文件传输用 P2P。
  • 不同主机上的进程通过 socket 交换报文。
  • 进程标识需要 IP 地址和端口号。
  • 应用协议规定报文类型、语法、字段语义和交互规则。
  • DNS 是分布式层次数据库和应用层协议，完成域名到 IP 的解析，也支持主机别名、邮件服务器别名和负载均衡。
  • 查询通常先到本地域名服务器；本地服务器无缓存时再查根、TLD、权威服务器。
  • 递归查询是被查询服务器代替请求方继续查询；迭代查询是返回下一步应查询的服务器信息。
  • 资源记录 RR 格式为 (name, value, type, ttl)，常见类型 A、NS、CNAME、MX。
  • FTP 使用分离的控制连接和数据连接，控制连接常用 TCP 21。
  • Email 系统由用户代理、邮件服务器、SMTP 和邮件读取协议组成。
  • SMTP 使用 TCP 可靠传输，服务器熟知端口 25，采用命令/响应交互，传输过程包括连接建立、邮件传送、连接释放。
  • 原始 SMTP 只支持 7 位 ASCII，MIME 用于传输多媒体内容和二进制附件。
  • HTTP 使用 TCP，服务器通常监听 80 端口；HTTP 是无状态协议。
  • 非持久 HTTP 每个对象单独建立 TCP 连接，响应时间约 2RTT + 对象传输时间。
  • 持久连接复用 TCP 连接，流水线持久连接可连续发送多个请求。
  • HTTP/2 将对象切为帧并交错传输，缓解应用层 HOL；HTTP/3 基于 QUIC/UDP，降低连接建立成本并减少队头阻塞。
  • Cookie 通过响应头、请求头、客户端文件和服务器数据库实现会话跟踪。
  • Web 缓存可在不访问源服务器时满足请求，降低响应时间和机构外链流量。
  • 条件 GET 使用 If-Modified-Since，若未修改可返回 304 Not Modified。
  • C/S 分发瓶颈在服务器上传和最慢客户端下载。
  • P2P 分发还利用所有对等方上传能力，因此 N 增大时通常比 C/S 更具扩展性。

公式与判定

C/S 分发
D_cs >= max(NF/us, F/d_min)

服务器至少上传 N 份，最慢客户端下载 1 份。

P2P 分发
D_p2p >= max(F/us, F/d_min, NF/(us + sum ui))

若所有 peer 上传相同 u，则 sum ui = Nu。

非持久 HTTP
T = 2RTT + object transmission time

单个对象无 DNS 时。

访问链路流量强度
aL/R

Web 缓存题常用于判断排队延迟。

易错点

  • 在 .com TLD 中注册域名时要放 NS 记录和权威 DNS 的 A 记录。
  • 在权威 DNS 中，Web 用 A 记录，邮件域用 MX 记录，邮件服务器名还需 A 记录。
  • HTTP 是 pull，SMTP 是 push。
  • Cookie 不是让 HTTP 变成有状态协议，而是在无状态协议上额外维护会话状态。
  • P2P 公式里不要漏掉服务器至少上传一份 F/us。

快速自查

Dcs >= max(NF/us, F/dmin)。

Dp2p >= max(F/us, F/dmin, NF/(us + Σui))。

xyz.com 的 NS 记录，以及 dns.xyz.com 的 A 记录。

01

UDP/TCP 首部：先按 bit 字段定位，再谈协议差异

考法：问 UDP 8B 首部、TCP 20B 固定首部、端口复用/分用、TCP 标志位。

定义

传输层用端口号标识进程；UDP 提供无连接报文服务，TCP 提供面向连接的可靠字节流服务。

解释

  • UDP 首部固定 8B：源端口、目的端口、长度、校验和，每个字段 16bit。
  • TCP 固定首部最小 20B，序号和确认号各 32bit；Data Offset 表示 TCP 首部长度，单位 4B。
  • TCP 连接由四元组标识：源 IP、源端口、目的 IP、目的端口。

做题步骤

  • 端口题先判断 UDP 还是 TCP；UDP 分用主要看目的端口，TCP 连接识别看四元组。
  • TCP 头长 = Data Offset * 4B；应用数据 = IP总长度 - IP头长 - TCP头长。
  • 标志位题重点看 SYN、ACK、FIN、RST。

为什么这样设计

  • UDP 头短适合短请求/实时业务，但可靠性要应用自己处理。
  • TCP 头部字段多，是为了支持可靠传输、流量控制、拥塞控制和连接管理。

作业/考试例子

DNS 常用 UDP 是因为一次请求响应短；HTTP 通常用 TCP/QUIC，传统 HTTP over TCP 依靠 TCP 保证字节流可靠有序。

02

TCP 序号与确认号：ACK 是下一个期待字节

考法：给 seq、ack、数据长度，问已经收到多少应用数据；问 SYN/FIN 是否占序号。

定义

TCP 序号是本段第一个数据字节的编号；确认号是接收方期望收到的下一个字节编号，采用累计确认。

解释

  • ACK=n 表示 n 之前的字节都已按序收到。
  • SYN 和 FIN 各占用一个序号，即使没有应用层数据。
  • 纯 ACK 不携带数据时通常不消耗序号。

做题步骤

  • 数据段长度 = IP总长度 - IP首部长度 - TCP首部长度。
  • 若收到 seq=x、len=L 的数据，正常确认号为 x+L。
  • 若是 SYN 或 FIN，要额外 +1。

为什么这样设计

  • 按字节编号而不是按段编号，可以让 TCP 自由拆分/合并应用数据。
  • 累计 ACK 降低 ACK 开销，也能容忍部分 ACK 丢失。

作业/考试例子

作业三分组 4 的 IP 总长度 56B，IP/TCP 首部各 20B，所以应用数据 16B；确认号从 0x846b41c6 到 0x846b41d6，差值 0x10=16。

03

三次握手：两端状态如何转移，为什么必须三次

考法：判断哪几个分组完成连接建立；写 SYN/ACK 标志位、seq/ack；解释第三次握手。

定义

三次握手让双方确认彼此的发送能力、接收能力和初始序号，建立 TCP 全双工连接。

解释

  • 第一次：客户端 CLOSED -> SYN_SENT，发送 SYN, seq=x。
  • 第二次：服务器 LISTEN -> SYN_RCVD，发送 SYN+ACK, seq=y, ack=x+1。
  • 第三次：客户端发送 ACK, ack=y+1 后进入 ESTABLISHED；服务器收到后进入 ESTABLISHED。

做题步骤

  • 看到 SYN=1,ACK=0 是第一次；SYN=1,ACK=1 是第二次；SYN=0,ACK=1 是第三次。
  • SYN 占一个序号，所以确认对方 SYN 时 ack 要 +1。
  • 第三次 ACK 可携带应用数据，但多数基础题中不携带。

为什么这样设计

  • 两次握手无法让服务器确认客户端已收到自己的初始序号。
  • 三次握手还能降低旧重复 SYN 导致错误连接建立的风险。

作业/考试例子

作业三中分组 1、2、3 分别是 H->S SYN，S->H SYN+ACK，H->S ACK，所以完成 TCP 三次握手。

三次握手状态转移

一侧当前状态事件/报文动作下一状态
客户端CLOSED应用主动打开发送 SYN, seq=xSYN_SENT
服务器LISTEN收到 SYN发送 SYN+ACK, seq=y, ack=x+1SYN_RCVD
客户端SYN_SENT收到 SYN+ACK发送 ACK, ack=y+1ESTABLISHED
服务器SYN_RCVD收到 ACK连接建立ESTABLISHED
04

四次挥手与 TIME_WAIT：为什么主动关闭方要等

考法：FIN/ACK 标志、两个方向分别关闭、TIME_WAIT 原因。

定义

TCP 连接释放通常需要两个方向各自发送 FIN 并被 ACK；主动关闭方最后进入 TIME_WAIT。

解释

  • FIN 表示本方向不再发送数据，但仍可接收对方数据。
  • 被动关闭方可能先 ACK，再等应用关闭后发送自己的 FIN，所以常见为四次挥手。
  • TIME_WAIT 保留 2MSL，确保最后 ACK 可重传，也让旧报文在网络中消失。

做题步骤

  • 谁先发 FIN，谁是主动关闭方。
  • FIN 与 SYN 一样占一个序号，ACK 要 +1。
  • 若第二、三步合并，可看到 ACK+FIN 同段，但逻辑上仍是两个方向关闭。

为什么这样设计

  • TCP 是全双工，关闭一个方向不等于另一个方向也立刻关闭。
  • TIME_WAIT 防止最后 ACK 丢失导致对方卡在 LAST_ACK，也防止旧连接报文污染新连接。

作业/考试例子

客户端发 FIN 后进入 FIN_WAIT_1；收到 ACK 后 FIN_WAIT_2；收到服务器 FIN 后回 ACK 并进入 TIME_WAIT。

05

流量控制：rwnd 是接收方状态，不是网络拥塞状态

考法：区分 rwnd/cwnd，给窗口求发送方最多未确认数据量。

定义

TCP 流量控制用接收窗口 rwnd 限制发送方未确认数据量，防止接收缓存溢出。

解释

  • 接收方根据接收缓存剩余空间通告 rwnd。
  • 发送方可发送窗口 = min(rwnd, cwnd)；rwnd 来自接收方，cwnd 来自拥塞控制。
  • 若 rwnd=0，发送方通常通过窗口探测避免永久等待。

做题步骤

  • 先看题目问保护谁：保护接收方是流量控制，保护网络是拥塞控制。
  • 计算未确认上限时取 min(rwnd,cwnd)。
  • 不要用 rwnd 推网络带宽，也不要用 cwnd 推接收缓存。

为什么这样设计

  • 接收应用读取速度可能慢于网络到达速度，因此需要 rwnd 反馈。
  • 把流量控制和拥塞控制分开，可以同时照顾端系统能力和网络能力。

作业/考试例子

若 rwnd=20KB、cwnd=12KB，则发送方最多只能有 12KB 未确认数据在网络中。

06

TCP Reno：cwnd 状态转移和作业三计算

考法：BDP 求最大窗口，Reno 平均窗口 0.75W，平均吞吐量，恢复时间；判断三重复 ACK/超时后的 cwnd。

定义

TCP Reno 用拥塞窗口 cwnd 控制发送速率，慢启动指数增长，拥塞避免线性增长，丢包后调整 ssthresh 和 cwnd。

解释

  • 慢启动：cwnd 从 1 MSS 开始，每 RTT 近似翻倍，直到达到 ssthresh。
  • 拥塞避免：每 RTT 约增加 1 MSS，形成线性增长。
  • 三重复 ACK：Reno 快速重传/快速恢复，ssthresh=cwnd/2，cwnd 降到约一半后线性增长。
  • 超时：认为拥塞严重，ssthresh=cwnd/2，cwnd=1 MSS，重新慢启动。

做题步骤

  • BDP 窗口段数 W = R*RTT/(MSS*8)。
  • 忽略慢启动时，Reno 锯齿平均窗口 = (W + W/2)/2 = 0.75W。
  • 平均吞吐量 = 平均窗口段数 * MSS * 8 / RTT。
  • 恢复时间 = (W - W/2) * RTT，因为拥塞避免每 RTT 加 1 段。

为什么这样设计

  • 慢启动快速探测可用带宽，但用 ssthresh 防止一直指数冲击网络。
  • 三重复 ACK 表示还有报文能到达，网络未完全崩溃；超时更严重，所以回到 1 MSS。

作业/考试例子

作业三 R=8Mbps、RTT=150ms、MSS=1500B，W=8e6*0.15/(1500*8)=100 段；平均窗口 75 段，吞吐量 6Mbps，恢复时间 50RTT=7.5s。

Reno 状态转移

当前状态事件cwnd/ssthresh 动作下一状态原因
慢启动ACK 到达且 cwnd < ssthreshcwnd 指数增长慢启动快速探测带宽
慢启动cwnd >= ssthresh改为每 RTT +1 MSS拥塞避免降低增长速度
拥塞避免3 个重复 ACKssthresh=cwnd/2, cwnd 降低快速恢复/拥塞避免仍有数据到达

07

IP/TCP 报文分析：把三层、四层、二层填充分开

考法：判断分组来源、三次握手、应用数据长度、以太网填充、TTL 推路由器数。

定义

报文分析题是逐层解封装：先按 IP 首部确定网络层字段，再按 TCP 首部确定连接状态和数据长度，最后才考虑以太网最小载荷。

解释

  • 应用数据长度 = IP Total Length - IP Header Length - TCP Header Length。
  • 以太网填充只为满足二层最小载荷，不改变 IP Total Length。
  • 经过路由器数 = 初始 TTL - 到达 TTL，前提是题目给出或能确定初始 TTL。

做题步骤

  • 来源判断看 IP 源地址，不要看 MAC 地址。
  • 连接建立看 TCP flags：SYN、SYN+ACK、ACK。
  • 填充判断看 IP 总长度是否小于以太网最小数据字段 46B。
  • TTL 推路由器数时先确认初始 TTL，不同系统初始值可能不同。

为什么这样设计

  • 分层字段各自有边界：IP 不知道以太网为了最小帧长补了什么。
  • TCP ACK 基于字节流，能与应用数据长度互相验证。

作业/考试例子

作业三分组 3 和 5 的 IP 总长度为 40B，小于以太网最小载荷 46B，所以以太网传输时填充 6B；这 6B 不属于 IP 数据报。

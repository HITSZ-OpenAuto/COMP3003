01

成帧与透明传输：接收方如何不看错边界

考法：给出字节串或比特串，让你判断填充/解填充后原始数据是什么。

定义

成帧是链路层给网络层数据加上边界、地址和差错检测信息，使接收方能识别一帧从哪里开始、到哪里结束。

解释

  • 透明传输的关键不是“看起来透明”，而是数据字段中出现定界符时，接收方仍能把它当普通数据。
  • 字节填充：若数据中出现 FLAG 或 ESC，就在它前面插入 ESC；接收端看到 ESC 后，把下一个字节按数据解释。
  • 比特填充：发送端每遇到连续 5 个 1，就插入 1 个 0；接收端看到连续 5 个 1 后，如果下一个 bit 是 0 就删除。

做题步骤

  • 先找定界符：PPP/HDLC 常用 01111110。
  • 再按方向判断：发送方向题目要插入填充位，接收方向题目要删除填充位。
  • 最后验证：真正帧边界只在首尾出现，数据区不应再裸露定界符模式。

为什么这样设计

  • 链路层不能限制上层数据内容，所以必须让任何数据模式都能安全通过。
  • 比特填充比直接删除定界符更稳，因为它只改变发送表示，接收端可逆恢复原始数据。

作业/考试例子

若数据中出现 01111110，发送端不会让它原样进入帧数据区，而是在连续 5 个 1 后插入 0，使接收方不会误判为帧结束。

发送方/接收方状态

一侧状态事件动作设计原因
发送方普通扫描读到普通字节/bit原样输出减少额外开销
发送方普通扫描读到 FLAG/ESC 或 5 个连续 1插入 ESC 或 0避免伪装成边界
接收方帧内扫描读到 ESC 或 5 个连续 1 后的 0删除填充符恢复上层原始数据
接收方帧内扫描读到未被填充的 FLAG判定帧结束边界检测唯一
02

CRC 与汉明距离：检测题先写能力边界

考法：手算 CRC 余数，或问检测/纠正 r 位错误需要多大最小汉明距离。

定义

CRC 把比特串看成模 2 多项式，发送端附加余数，使整帧能被生成多项式整除；汉明距离描述合法码字之间最少不同 bit 数。

解释

  • CRC 除法用异或，不借位、不进位；生成多项式阶数为 r，就在数据后补 r 个 0。
  • 接收端余数为 0 只表示“未检测到错误”，不是数学上保证绝对无错。
  • 最小汉明距离 ds：检测 r 位错需要 ds >= r + 1；纠正 r 位错需要 ds >= 2r + 1。

做题步骤

  • CRC 题：写 D 后补 r 个 0，做模 2 除法，余数不足 r 位就在左侧补 0。
  • 纠错题：看到“纠正”用 2r+1，看到“检测”用 r+1。
  • 不要把 CRC 当纠错码；链路层常用 CRC 做检测，错了通常丢弃或请求重传。

为什么这样设计

  • CRC 适合硬件高速实现，能高概率检测突发错误。
  • 汉明距离公式来自码字球半径：纠错需要错误球互不重叠，所以门槛更高。

作业/考试例子

题目问“纠正 2 bit 错误所需最小汉明距离”，直接写 ds >= 2*2+1 = 5。

03

以太网帧与 802.1Q：最小帧长、填充和 VLAN ID

考法：问 64B 最小帧、46B 最小载荷、IP 总长度 40B 时填充多少；VLAN 题问标签插在哪里。

定义

以太网帧是 LAN 中 MAC 层传输单位；802.1Q 在源 MAC 后插入 4B 标签，用来在 trunk 链路中标识 VLAN。

解释

  • 以太网最小帧长 64B 通常不含前导码和 SFD，包含目的 MAC、源 MAC、类型、数据、FCS。
  • 普通以太网头尾开销为 6+6+2+4=18B，所以数据字段最小 46B。
  • 802.1Q 标签为 4B：TPID 2B + TCI 2B；TCI 内包含 PCP 3bit、DEI 1bit、VLAN ID 12bit。

做题步骤

  • 填充题只看以太网数据字段是否小于 46B。
  • 若 IP 数据报总长度就是以太网载荷长度，填充 = max(0, 46 - IP总长度)。
  • VLAN 帧题要记住标签位置：源 MAC 后、Type/Length 前。

为什么这样设计

  • 最小帧长服务于 CSMA/CD 冲突检测：帧太短会导致发送方发完后才知道远端冲突。
  • VLAN ID 放在二层帧中，使一条 trunk 物理链路能承载多个逻辑广播域。

作业/考试例子

作业三中 IP 总长度 0x0028=40B，进入快速以太网时数据字段小于 46B，因此要补 6B；注意补的是以太网填充，不是 IP 总长度字段的一部分。

04

CSMA/CD：状态过程和最小帧长为什么绑定

考法：解释先听后发/边发边听，计算最小帧长或判断短帧为什么危险。

定义

CSMA/CD 是共享式以太网的随机访问协议：发送前监听信道，发送中检测冲突，冲突后发送 jam 信号并随机退避。

解释

  • 最小帧发送时间必须 >= 最坏情况下冲突往返传播时延 2τ。
  • 若 L/R < 2τ，发送方可能已经发完并认为成功，但远端冲突信号还没传回来。
  • 交换式全双工以太网通常不再运行 CSMA/CD，但考试用它考传播时延、传输时延与冲突检测边界。

做题步骤

  • 计算题写 Lmin/R >= 2d/v，整理得 Lmin >= 2dR/v。
  • 单位统一：R 用 bit/s，传播速度 v 用 m/s，距离 d 用 m。
  • 若题目问有效速率，要额外考虑冲突、退避、帧间隔等开销。

为什么这样设计

  • 冲突检测不是事后统计，而是要求发送方还在发送时就能听到冲突。
  • 退避随机化是为了避免两个站点碰撞后再次同步重发、反复碰撞。

作业/考试例子

以太网 64B 最小帧可理解为在典型最大网络直径和 10Mbps 速率下，为冲突检测留出的下界。

发送方状态转移

状态事件动作下一状态设计原因
监听信道空闲开始发送发送中减少明显冲突
监听信道忙继续等待监听避免立刻叠加冲突
发送中未检测到冲突且发完认为发送成功监听共享介质无链路层 ACK
发送中检测到冲突发送 jam，停止发送退避让所有站点知道本次失败

05

可靠传输：停等、GBN、SR 的发送方/接收方状态

考法：给窗口和丢包事件，问 ACK 含义、重传哪些帧、序号空间约束。

定义

可靠传输用序号、ACK、定时器和重传机制，在可能丢帧/乱序的链路上实现可靠交付。

解释

  • 停等协议一次只允许 1 个未确认帧，状态最简单，但 RTT 大时利用率低。
  • GBN 发送窗口可大于 1，接收窗口 Wr=1，只接收按序帧；乱序帧丢弃，ACK 是累计确认。
  • SR 发送方和接收方都有窗口，接收方缓存乱序帧，ACK 是逐帧确认；窗口通常 <= 序号空间一半。

做题步骤

  • GBN 丢第 k 帧：接收方丢弃 k 之后的乱序帧，发送方超时后从 k 回退重传。
  • SR 丢第 k 帧：接收方可缓存 k 之后的帧，发送方只重传 k 或超时帧。
  • 窗口大小题：GBN Ws <= 2^k - 1；SR W <= 2^(k-1)。

为什么这样设计

  • GBN 牺牲带宽重传来换取接收端简单，不需要乱序缓存。
  • SR 牺牲接收端缓存和更复杂 ACK，换取更少无谓重传。

作业/考试例子

k=3 位序号时，GBN 最大发送窗口 7；SR 单边窗口通常最多 4，否则新旧同序号帧可能混淆。

06

交换机、VLAN、PPP：按动作顺序答题

考法：交换机收到帧后学习/转发/过滤/泛洪；VLAN 隔离广播域；PPP 提供哪些功能。

定义

交换机是链路层设备，基于源 MAC 自学习，基于目的 MAC 转发；VLAN 在二层逻辑隔离广播域；PPP 是点到点链路层协议。

解释

  • 交换机先学习源 MAC 到入端口，再查目的 MAC。
  • 目的端口未知就泛洪；已知且不同于入端口就转发；已知且等于入端口就过滤。
  • PPP 提供成帧、透明传输、差错检测和链路控制，但不提供可靠重传和流量控制。

做题步骤

  • 交换机题不要先查目的地址，必须先写学习源地址。
  • VLAN 题先判断端口类型：access 不带标签接主机，trunk 带 VLAN ID 接交换机。
  • PPP 功能题用排除法：它不是 TCP，不负责端到端可靠传输。

为什么这样设计

  • 自学习让交换机即插即用，不需要手工配置完整 MAC 表。
  • VLAN 用逻辑划分替代物理拆网，降低布线成本，也限制广播范围。

作业/考试例子

A 从端口 1 发给未知的 B，交换机记录 A->1，然后向除端口 1 之外的端口泛洪；之后 B 回复时，交换机学到 B 的端口。
